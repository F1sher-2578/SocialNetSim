## 1. 现状与约束

**现状**（读 `index.html`、`main.py`、`README.md` 所得）：

- 前端只有一个文件 `socialsim/app/templates/index.html`（630 行），原生 JS 用 `fetch` 取数后拼 HTML 字符串，样式自己写，配色借用 Arco 色值（`#00b42a / #ff7d00 / #f53f3f / #1d2129 / #86909c`）。没有任何 UI 框架和图表库；"图表"只有用 `<span class="bar">` 拼出来的进度条。
- `main.py` 已挂载 `/static`（目录目前为空）和 `/reports`（指向 `results/`）。首页用 `read_text()` 直接返回，**没有经过 Jinja**，所以 Vue 的 `{{ }}` 语法不会冲突。
- 可直接可视化的数据：
  - `results/*.json`：消融、泛化、规避曲线、攻击成功率随 ε 的变化、阈值表、62 段视频逐条得分等；
  - `results/reports/*/report.json`：**每帧都有分数和 9 个专家分量 `parts`**，另有语音 / OCR 命中、各阶段耗时；
  - `data/socialsim.db`：194 个用户、1750 条关注边、11 个团伙。
- 两个数据缺口：
  - `/api/moderate/upload` 返回前会 `pop("frames")`，但同目录下的 `report.json` 保留了逐帧数据，前端按 `report_url` 换成 `report.json` 就能取到，**后端不用改**；
  - 水军检测的 ROC 点在写 summary 时被删掉了，要画 ROC 曲线需要后端顺手保存一份降采样后的点（见 §9.8）。

**约束如何落实**：每个候选库都核对了三件事：许可证字段、最近一次发版日期、npmmirror 上能否单文件直取。推荐栈的文件逐个用 `curl` 下载并记录字节数和 SHA-256，再用无头 Chrome 加 `--host-resolver-rules="MAP * ~NOTFOUND"`（任何外网域名都解析失败）实际跑一遍。

## 2. 前置发现：npmmirror「单文件直取」有白名单

npmmirror 的 unpkg 式文件服务只对白名单内的包开放，原因是"避免被当作网盘滥用"（见 [cnpm/unpkg-white-list](https://github.com/cnpm/unpkg-white-list)）。不在名单内的包访问 `/files/` 会返回：

```
403 {"error":"[FORBIDDEN] \"@tabler/core\" is not allow to unpkg files, see https://github.com/cnpm/unpkg-white-list ..."}
```

2026-10-16 实测：

| 可以单文件直取（200） | 不允许（403，只能下 tgz 再解压） |
|---|---|
| vue、element-plus、@element-plus/icons-vue、echarts、tdesign-vue-next、naive-ui、daisyui、@tailwindcss/browser、bootstrap、bootstrap-icons、chart.js、@antv/g6、@antv/g2、cytoscape、sigma、graphology、alpinejs、vuetify、quasar | @tabler/core、@tabler/icons-webfont、admin-lte、@coreui/coreui、@arco-design/web-vue、flowbite、apexcharts、vis-network、plotly.js-dist-min、vue-element-plus-x、@tdesign-vue-next/chat、@awesome.me/webawesome |

tgz 的地址格式是 `https://registry.npmmirror.com/<包>/-/<名>-<版本>.tgz`，会 302 跳转到 `cdn.npmmirror.com`，实测都能下载。用 Python 标准库 `tarfile` 即可取出需要的文件，同样不需要 Node。

**建议**：直接把 vendor 文件**提交进 git**（推荐栈约 2.8 MB，`.gitignore` 没有排除 `static/`）。组员 `git clone` 下来就能离线用，`setup.sh` 不必多一步联网。另附一个可选的拉取脚本，只在升级版本时使用（见 §10.4）。

### 3.3 逐个点评

- **Tabler**：纯 HTML/CSS 方案里最好看的一个，演示页超过 120 个（Activity、Chat、Logs、Uptime monitor、Data grid、Steps、Tracking 等），MIT 许可。缺点有三：没有响应式框架，复杂交互全靠手写；npmmirror 不能单文件直取，图标字体约 0.7 MB；**它自带的图表示例用的是 ApexCharts**，1.5.0 起还专门在文档里说明了 ApexCharts 的双许可（见 [Tabler Charts 文档](https://tabler.io/docs/components/charts)），所以照抄它的图表示例会把许可证问题带进来。
- **AdminLTE 4**：2026-05 才发布 v4.0.0 正式版，已改为 Bootstrap 5.3 + 原生 JS（[迁移指南](https://adminlte.io/blog/adminlte-upgrading-from-v3-to-v4/)）。观感偏传统，表格交互和上传都要另配插件，对这个项目没有优势。
- **CoreUI Free**：免费版缺日期选择、多选、Stepper、Smart Table 等（[PRO 标注](https://github.com/coreui/coreui)），还不如直接用 Bootstrap。
- **Element Plus**：官方文档专门写了"浏览器直接引入"的用法（全局变量 `ElementPlus`、建议锁定版本、DOM 内模板要写双闭合标签），zh-CN 语言包可直接 `app.use(ElementPlus, { locale: ElementPlusLocaleZhCn })`（[安装](https://element-plus.org/zh-CN/guide/installation) / [国际化](https://element-plus.org/zh-CN/guide/i18n.html)）。几乎所有组件样式都基于 CSS 变量，运行时就能换主题（[主题](https://element-plus.org/zh-CN/guide/theming)），暗色模式只需给 `html` 加 `dark` 类并引入 2.9 KB 的 `css-vars.css`（[暗黑模式](https://element-plus.org/zh-CN/guide/dark-mode)）。浏览器要求：2.5.0 起需要 Chrome / Edge 85+、Firefox 79+、Safari 14.1+。
- **Arco Design Vue**：组件和视觉都很好，现有配色也取自 Arco，但维护基本停了：issue #3548（2025-05）"arco design vue 不维护了吗"至今未关闭，React 仓库的 #2926 也在讨论"使用 Arco 还是 Semi"（[#2926](https://github.com/arco-design/arco-design/issues/2926)、[SegmentFault 分析](https://segmentfault.com/a/1190000047496193)）。npmmirror 也不能直取。**新开发不建议选它**；想保留 Arco 的观感，在 Element Plus 上覆盖主题色即可（§8.3）。
- **TDesign**：组件最全（自带 Guide、Comment、QRCode 等），更新最快。缺点：UMD 包里的 `t-icon` 会自动插入一个 `<script>` 去加载 `https://tdesign.gtimg.com/icon/0.4.5/fonts/index.js`（已在 `tdesign.min.js` 里找到这个地址），离线时要自己托管这个文件并给每个图标加上 `url` 和 `:load-default-icons="false"`；另外 `@tdesign-vue-next/chat@0.7.0` 只有 `es/index.mjs`，还依赖一串需要打包器解析的 npm 包，不构建就用不了（[TDesign Chat](https://tdesign.tencent.com/chat/)）。
- **Naive UI**：官方从 2.30.3 起提供 UMD，并说明自闭合标签有问题（[UMD 文档](https://github.com/tusen-ai/naive-ui/blob/main/demo/pages/docs/umd/zhCN/index.md)）。包体积最大（2.18 MiB），而且 2022 年维护者曾明确表示不希望库被这样用（[讨论 #2755](https://github.com/tusen-ai/naive-ui/discussions/2755)）。
- **daisyUI / Flowbite**：`daisyui.css` 只包含组件类，`flex`、`gap-3` 这类布局工具类一个都没有（实测为 0）；`flowbite.min.css` 是 Tailwind v4.0.15 的产物，只包含 Flowbite 官网示例用到的类。两者要么在浏览器里跑 `@tailwindcss/browser` 做 JIT（Tailwind 官方："designed for development purposes only, and is not intended for production"），要么就得构建，和"免构建"的约束冲突。另外 Tailwind 的 preflight 重置会和其他组件库的样式打架，不能混用。
- **其他被排除的**：
  - PrimeVue 5 起改用 PrimeUI 许可，不再是 MIT（[PrimeTek 公告](https://primeui.dev/nextchapter)）；
  - Ant Design Vue 最新版 4.2.6 发布于 2024-11-11，之后再无新版本；
  - React 19 已移除 UMD 构建（[React 19 升级指南](https://react.dev/blog/2024/04/25/react-19-upgrade-guide#umd-builds-removed)），Semi、Arco React、antd 6 都无法简单地免构建使用；
  - Preline 5 的许可证是"MIT + Preline UI Fair Use License"，不够宽松。

### 3.4 结论

在"免构建 + 离线 + 中文 + 交互复杂"这几个条件下，**Vue 3 + Element Plus 的综合得分最高**：

- 文件全部在 npmmirror 白名单里；
- 运行时不访问任何 CDN（在 bundle 里搜不到外部地址）；
- 官方文档直接覆盖了浏览器引入、中文语言包和 DOM 内模板的注意事项；
- 组件覆盖最完整；
- 国内高校用得最多，组员和助教都熟，中文资料也多。

TDesign 和它几乎打平，差在图标默认走 CDN、Chat 组件要构建；Tabler 则适合"不想引入框架"的团队。

## 4. 社交信息流页面怎么做

### 4.1 业内的做法：一套设计令牌，两种视觉语言

- **Shopify**：管理后台用 Polaris 设计系统，店铺前台用商家自己的品牌主题。Polaris 2017 年发布时就明确只用于商家后台，不用于顾客看到的店铺（[Meet Polaris](https://medium.com/michaelphill/meet-polaris-the-new-look-for-the-shopify-admin-603b3d810822)）；嵌入店铺的插件区块还被要求继承主题的字体和颜色（[Theme app extensions UX](https://shopify.dev/docs/apps/build/online-store/theme-app-extensions/ux)）。
- **Y Social（意大利 CNR 的社交媒体数字孪生，和我们是同类项目）**：README 把"Public Web Interface"（仿 X / Bluesky 的微博式时间线）和"Admin Panel"（仿真配置与监控）分成两部分，前端模板用的是 Friendkit（[YSocial](https://github.com/YSocialTwin/YSocial)）。
- **Bluesky Ozone（开源审核台）**：审核台是一个独立的 Next.js 应用，但"Take Action"面板左侧直接把被举报的帖子按原样渲染出来，右侧是事件日志；点"Peek"可以跳回 Bluesky 客户端看原帖（[Ozone 用户指南](https://github.com/bluesky-social/ozone/blob/main/docs/userguide.md)）。
- **X**：把处置结果直接显示在用户端信息流里，例如 "Visibility limited: this Post may violate X's rules against Hateful Conduct"（[执法选项](https://help.x.com/en/rules-and-policies/enforcement-options)、[Freedom of Speech, Not Reach](https://blog.x.com/en_us/topics/product/2023/freedom-of-speech-not-reach-an-update-on-our-enforcement-philosophy)）。

**结论**：应该是**两种视觉语言，但共用一套设计令牌**（颜色、字体、圆角、阴影都来自同一组 CSS 变量，组件库也只用一套）。

- **信息流页**用"C 端布局"：三栏、留白多、圆角头像、互动栏、话题高亮，不出现表格；
- **其他 5 页**用"控制台布局"：侧边导航、信息密度高、表格和图表为主；
- 两者通过一个 **「审核透视」开关**连起来：打开后，把审核台的信息叠加到 C 端界面上（水军真值、检测分、判定徽章、被拦截内容折叠，类似 BotSight 浏览器插件在推特时间线上叠加评分）。点帖子或用户，就打开 Ozone 式的右侧抽屉，左边是对象本身，右边是证据和事件。这是平台演示里最直观的讲法："普通用户看到什么"和"平台看到什么"一键切换。

### 4.3 用 Element Plus 实现信息流（建议版式）

```
┌ 左栏 220px ────┐┌ 中栏 600px（时间线）──────────────┐┌ 右栏 320px ─────────┐
│ 头像 + 昵称    ││ 发帖框（el-input，autosize，     ││ 平台概览（2×4 小卡） │
│ 首页/关注/话题 ││  maxlength=280，show-word-limit）││ 热门话题榜（带排名  │
│ [审核透视] 开关││ 发帖后的审核回执卡                ││  和"热/新/沸"标签） │
│                ││ el-segmented：热门 | 关注         ││ 可疑账号 Top5        │
│                ││ ───── 帖子 ─────                  ││ 最近拦截动态         │
│                ││ 头像  昵称 @账号 · 3 分钟前       ││                      │
│                ││       正文：#话题# 和 @提及 高亮  ││                      │
│                ││       💬 12  🔁 3  ♥ 48  ···      ││                      │
└────────────────┘└───────────────────────────────────┘└──────────────────────┘
```

- **帖子**：X 式"整列连续、用 1px 分隔线"比每条一张卡片更像真实平台。头像用 `el-avatar`（现在是 emoji，可以加一个按团伙着色的描边）；时间用原生的 `Intl.RelativeTimeFormat('zh-CN')`；`#话题#` 和 `@提及` 用正则包成 `<span class="topic">`，**用户内容一律用 `{{ }}` 渲染，不要用 `v-html`**；互动栏用 Element 图标 `ChatDotRound`、`Share`、`Star`，悬停变色；`···` 用 `el-dropdown`（举报 / 查看审核详情）。
- **用户视角下的审核结果**（参照 X 的提示条）：
  - `block`：折叠成灰色占位条"该内容因违反社区规定已被拦截"，演示模式下可以点开；
  - `review`：在帖子底部加一条浅灰提示"可见性受限：疑似违规，待人工复核"；
  - `pass`：什么都不显示。
- **审核透视开（审核台视角）**：
  - 昵称后加红色"真值：水军"标签；
  - 检测分用 0–5 分的小徽章（参照 Botometer，见 §7.3），按红黄绿着色；
  - 显示判定徽章、风险分和风险标签；
  - 对被水军撑起来的热门帖加"🔥 水军推高 63%"徽章：取 `/api/exposure` 里每帖的 `bot_like_ratio`，按 `post_id` 对上即可，**后端不用改**。
- **抽屉**：点用户打开"账号画像"（`el-descriptions` + 风险仪表 + 五组特征雷达 + 前 3 条证据 + "在水军检测中查看"）；点帖子打开"帖子详情"（`/api/post/{pid}`，含评论及其审核状态）。
- **发帖回执**：发布后在发帖框下方弹出回执卡，包含判定徽章、一个小仪表（`el-progress type="circle" :width="48"`）、风险标签，拦截时用 `el-result` 的形式。
- **不建议用小红书式瀑布流**：现在的帖子基本是纯文本加话题，微博 / X 的单列时间线更合适。

### 5.2 我们需要的 7 类图怎么用 ECharts 画

| 图 | ECharts 写法要点 | 数据来源 |

### 6.2 用真实数据实测（只读访问 `data/socialsim.db`）

- networkx 3.6.1 已经在 `requirements.txt` 里，用不着新增依赖。关注图中有边的节点 162 个、边 1750 条：`spring_layout` 用时 **0.075 s**，`forceatlas2_layout(max_iter=300)` 用时 **0.144 s**，Louvain 社区划分 0.009 s（得到 7 个社区）。在每次请求时实时算都没问题。
- 把预计算的坐标交给 ECharts（`layout:'none'`），194 节点、1750 边、12 个类别（正常用户 + 11 个团伙）断网下渲染正常。
- G6 5.1.1 用 11 个 `hull` 插件给每个真值团伙画轮廓，也能渲染，**但画出来的轮廓互相大面积重叠，图很乱**。原因是 **32 个水军账号没有任何关注边**（C1-boost 4 个、C2-smear 10 个、C3-hashtag_push 12 个、C5-spam 6 个），布局算法把它们甩到了外圈，轮廓被撑得很大。
- 由此得出数据层面的结论：**只看关注图，"高亮团伙"讲不清楚**。这几类水军之间没有关注关系，它们的协同体现在"同时去点赞、评论同一个目标"。`bot_detector.py` 已经算出了这张协同行为图：`sync_pairs` 中权重 ≥2 的边存进了 `df.attrs["graph"]`，后面又做了 Louvain，`unsupervised_coordination` 就是在这张图上跑出 5 个纯度 100% 的社区。

### 6.3 推荐方案

1. **用 ECharts `series-graph`**，增加一个后端接口 `GET /api/graph?kind=follow|sync`（约 30 行，见 §9.8）。后端用 networkx 算好坐标（固定 seed，保证每次演示的图形一样）、算好社区，再一起返回。
2. 页面上用 `el-segmented` 提供两组切换：
   - 边类型：**关注关系 / 协同行为**；
   - 着色方式：**按真值团伙 / 按无监督社区 / 按检测分**。"真值团伙"和"无监督社区"来回切换，就能直观看到检测器在不用标签的情况下圈出了哪些人。
3. 视觉编码：
   - 正常用户用小号灰点；
   - 水军颜色的**色相代表策略**（boost / smear / hashtag_push / follow_farm / spam 各一种色相），**明度代表规避等级**（ev0 深 → ev2 浅）；
   - 节点大小映射检测分；被检测器标记的节点加红色描边；
   - 孤立账号单独放在一个"零关注水军"区域（这本身就是一种水军特征：新注册、没有任何关注）。
4. 交互：图例开关团伙；悬停高亮邻居；点击节点打开判定依据抽屉；ECharts 6 的 `thumbnail` 显示缩略导航。
5. **只有确实想画轮廓时才加 G6**，而且应该画在"协同图上的 Louvain 社区"上（这些社区本身在空间上就是聚在一起的），不要画在包含孤立点的真值团伙上。

```js
for (const [k, c] of Object.entries(ElementPlusIconsVue)) app.component(k, c);
app.use(ElementPlus, { locale: ElementPlusLocaleZhCn }).mount('#app');
```

- **为什么用字符串模板，不把模板直接写在 HTML 里**：Vue 文档说明，DOM 内模板有三条限制（标签名和属性名不区分大小写、必须显式写闭合标签、`<table>` / `<ul>` 等元素内部有放置限制），而**字符串模板和 `<script type="text/x-template">` 都不受这些限制**（[Vue：in-DOM Template Parsing Caveats](https://vuejs.org/guide/essentials/component-basics.html#in-dom-template-parsing-caveats)）。Element Plus 官方也提醒，DOM 内模板要写成 `<el-table-column></el-table-column>` 这样的双闭合形式。
- **进阶可选：ES 模块 + import map**（同样已实测）：把 Vue、EP、图标、ECharts 换成各自的 ESM 构建（文件清单见 §10.2），在 `<script type="importmap">` 里映射，各页面写成 `export default {…}`，用 `import` 互相引用。这是 Vue 官方给出的免构建拆分方式（[Vue Quick Start：Using Vue from CDN](https://vuejs.org/guide/quick-start.html#using-vue-from-cdn)），代码更清爽。**限制是只能通过 http 访问**：ES 模块在 `file://` 下会被浏览器拦截，Vue 文档有说明，本机实测也是 file:// 下失败、http 下正常。主应用由 FastAPI 提供，不受影响；但会被直接双击打开的独立报告 HTML 只能用 UMD。

### 8.3 主题令牌（沿用现有的 Arco 色板）

Element Plus 的 `--el-color-primary-light-3/5/7/8/9` 和 `-dark-2` 在 CSS 里是**写死的十六进制值**，不会根据主色自动计算（已在 `index.css` 里确认）。所以只覆盖 `--el-color-primary` 时，悬停态和浅色背景仍然是默认蓝色。下面的值按 Element Plus 的 SCSS 公式算出：light-N 是和白色按 N×10% 混合，dark-2 是和黑色按 20% 混合。用同一个公式算默认色 #409eff，得到 #79bbff、#c6e2ff、#337ecc，和官方值一致。

## 9. 逐页改造方案

### 9.0 全局外壳（每页都受益）

- **布局**：`el-container`；左侧 `el-aside` 宽 220px、可折叠；`el-menu` 按讲解顺序分组，系统结构一看就懂：
  - **用户端**：信息流
  - **红队（攻击方）**：水军控制台
  - **蓝队（防御方）**：水军检测、内容审核、安全助手
  - **评估**：攻防实验
- **顶栏**：项目名；"本地沙箱 · 不连接真实平台"标签；仿真时间；全局"审核透视"开关；"演示导览"按钮（`el-tour`，答辩时一步步带老师看重点）。
- **路由**：用 `location.hash`（如 `#/detect`）配合 `<keep-alive><component :is>`，页面状态不丢，刷新后还停在原页。
- **图表工程规范**（避免常见的坑）：
  - ECharts 实例用 `shallowRef` 或普通变量保存，**不要放进 `ref` / `reactive`**（深层代理会拖慢甚至弄坏 ECharts）；
  - 放在标签页里的图要用 `el-tab-pane lazy`，并在组件 `onMounted` 时再初始化。隐藏容器的尺寸是 0，提前初始化画出来的图是空白；
  - 用 `ResizeObserver` 调用 `chart.resize()`，组件卸载时调用 `dispose()`。

```js
// charts.js 里的通用封装
SN.useChart = (elRef, getOption, deps) => {
  const { onMounted, onBeforeUnmount, watch } = Vue; let chart = null, ro = null;
  onMounted(() => { chart = echarts.init(elRef.value, 'socialsim'); chart.setOption(getOption());
    ro = new ResizeObserver(() => chart && chart.resize()); ro.observe(elRef.value); });
  if (deps) watch(deps, () => chart && chart.setOption(getOption(), { notMerge: true }));
  onBeforeUnmount(() => { ro && ro.disconnect(); chart && chart.dispose(); });
  return () => chart;
};
```

### 9.5 安全助手

- **三栏布局**：
  - 左栏 260px：样例库，`el-collapse` 分成直接注入 / 混淆注入 / 间接注入 / 良性四组，点击即填入；

```python
def get(url: str) -> bytes:
    with urllib.request.urlopen(url, timeout=120) as r:
        return r.read()
for pkg, ver, path, dest, sha in FILES:
```

## 11. 风险与注意事项

1. **DOM 内模板的限制**：模板直接写在 HTML 里时，组件名和属性名必须用 kebab-case，不能自闭合，表格和列表元素内部也有放置限制。**统一用 JS 字符串模板就能整体绕开**（§8.2）。
2. **ES 模块不能在 file:// 下运行**：主应用没有影响；独立报告只能用 UMD（§9.7）。
3. **改主题色要连带改变体**：Element Plus 的 `light-*` / `dark-2` 是写死的值，必须一起覆盖（§8.3）。
4. **ECharts 6 默认主题变了**：网上大量 v5 时代的示例截图和现在的配色不一样，属于正常现象；想要旧观感就引入 `theme/v5.js`。
5. **图表放在隐藏容器里会变空白**：标签页要开 `lazy`，初始化后用 `ResizeObserver` 跟踪尺寸，卸载时 `dispose()`（§9.0）。
6. **指标 JSON 的结构还在变**：`bot_detection_metrics.json` 今天 08:02 被重写成 `models / evasion_curve / evasion_generalization / generalization.{all_features,no_profile_features}`。现在的 `index.html` 已经同时兼容 `bm.models?.RandomForest || bm.RandomForest` 两种写法；新前端应该**在 `api.js` 里统一做兼容**，页面组件只读兼容后的结构。另外仓库里还有 `results/bot_detection_live.json`（网页上"重新评估"时的即时结果），需要和组员约定前端到底读哪一个。
7. **许可证合规**：vendor 目录里保留各自的 LICENSE，ECharts 还要保留 NOTICE；**不要照抄 Tabler 或 Flowbite 的图表示例**，它们基于 ApexCharts（5.1 起非 MIT）；Bluesky 客户端只能借鉴布局，品牌素材不能用。
8. **XSS**：Vue 的 `{{ }}` 默认会转义。帖子、评论、注入样例这些用户内容**一律不要用 `v-html`**；话题高亮要先拆成文本片段，再用 `v-for` 渲染。
9. **离线自查**：答辩前关掉 Wi-Fi，用"硬性重新加载"打开页面，在浏览器开发者工具的网络面板里确认没有任何外部请求。也可以按附录 A 的方法，用 Chrome 加 `--host-resolver-rules="MAP * ~NOTFOUND"` 跑一遍。
